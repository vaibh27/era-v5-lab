# Clean-document audit: code-cpp (Sourav Dhar)

**Pack:** `code-cpp` (starcoderdata C/C++). **Raw:** sample-v0 Part_1 `part-00000.parquet` (41,116 docs), Part_2
`part-00001.parquet` (14,429). **Cleaned:** the #244 cleaning (`tokenizer_sample_v0_clean/train/code-cpp/`), compared by
`doc_id`. The cleaning job's rule counts (`jobs/2026-11-02-tokenizer-sample-v0-clean/logs/…-rule-counts.csv`) show,
among others, DA-B3-001, DA-E1-005, DA-E1-007, DA-E4-010 and DA-B4-009 acting on this pack.

**Method:** 25 Part_1 and 10 Part_2 documents drawn at random (`random.Random(20261123).sample`, Part_1 first) from the
documents the cleaner changed or dropped, the viewer's *Only changed* set: 28,723 in Part_1 (698 dropped) and 10,087 in
Part_2 (259 dropped). The sample therefore measures what the cleaner does, not how common a disease is in the pack. Each
document was read with its raw → cleaned diff and checked by script (StarCoder tags and placeholders, emails, licence
words, generated-file markers, secret-like strings, long lines, base64-like runs, hex-byte density, non-ASCII, control and
invisible characters, repeated lines, brace balance). Main's `spec_v1_1/clean.py` (54a370aa) gives byte-identical output
to the sample on all 35 raw documents, so every finding below also holds for the current cleaner.

## What the cleaner does on this pack

- **Removes StarCoder's metadata line** (`<reponame>…`, `<filename>…`, `<gh_stars>…`, alone or combined; DA-B3-001):
  25 of the 34 kept documents. Never touches the code body.
- **Replaces `<NAME>` with `AUTHOR`** (DA-B4-009): 10 documents, all in comments. In two of them StarCoder had masked a
  comment title and a university name, not a person; harmless. `<EMAIL>` is kept on purpose: it is the tag TSAI asks
  for (`spec_v1/build/build_clean.py:66`).
- **Removes licence headers of 5+ lines** (DA-E4-010): 8 documents: Apache (TensorFlow, XLS, NVIDIA), ASF "Licensed to
  the Apache Software Foundation" (`4545922f9d37bf4d`; the DA-E4-007 gap #78 found on js-ts is not in this rule), Qt
  LGPL/GPL, GPL, Google BSD, LLVM. One- and two-line copyright or licence notes stay, by design.
- **Normalises CRLF to LF** (1 document) and **removes a BOM** (1).
- **Drops generated files** (DA-E1-005): `87310cafcc7af1d6`, "Code generated by IfcQuery EXPRESS generator". Right.

No real name, email or secret in any cleaned document of the sample.

## Findings

1. **A licence block behind a one-line editor comment is kept** (`bfb4e3b5db49c1ff`, fix, E4). The file starts with an
   Emacs modeline (`/* -*- Mode: C++; … -*- */`), then a 15-line Apache header. DA-E4-010 tests only the first comment,
   which is 1 line, so nothing is removed; with the modeline taken off, the rule removes the header. Over Part_1 +
   Part_2, 197 documents (0.35%) have a licence block that DA-E4-010 would remove sitting behind a short first `/* … */`
   comment; the most common first lines are Emacs `-*- mode -*-` and vim modelines. Proposal (v1.1 backlog): when the
   first comment is under 5 lines with no licence word, keep it and test the next comment block.
2. **The licence removal can take the next comment with it** (`e2331602ffd4726c`, fix, E4). After the LLVM header come a
   blank line and `// #define LLVM_LIBC_PRINTF_DISABLE_INDEX_MODE 1 // This will be a compile flag.` DA-E4-010 lets a
   `//` run continue over single blank lines, and the run still passes the licence-density bar, so that line is removed
   too. The code is unaffected; a real comment (the note on the flag the `#ifndef`s test) is lost. Over Part_1 + Part_2,
   197 of the 10,783 documents DA-E4-010 changes (1.8%) end their removed block with a paragraph that has no licence word;
   34 of them are author or contact lines (fine to lose). Of the first 40 listed, 27 were real comments: file
   descriptions ("This file implements …"), test notes, `// clang-format off`, `// No include guard…`. Proposal (v1.1
   backlog): end the block at a blank line when the paragraph after it has no licence word.
3. **Mojibake in comments is not treated** (`579eed50abc89e4a`, fix, E5). Five Japanese comment lines (two blocks) were
   EUC-JP text read as GBK upstream. Encoding them back as GBK and decoding as EUC-JP restores the Japanese exactly, but
   the code family has no E5 medicine. Small (5 of 1,134 lines; the rest of the file is fine). Proposal (backlog, low): a
   code E5 check that tries the GBK → EUC-JP round trip on comment lines and keeps it only when the result is valid
   Japanese. Prevalence not measured.
4. **The shared F1 never acts on code packs** (pack-wide; no sample document affected). `clean()` passes each row's
   `lang_label` to F1, and every code pack's rows carry `lang_label: "code"` (the 38-pack rehearsal's
   `clean_job_summary.json` lists `language_tags: ["code"]` for cadj-* and all code-* packs). F1 runs only for labels in
   `_F1_LANGS` (`cpp`, `go`, `java`, …), so for "code" it returns keep (`spec_v1_1/clean.py`, `f1()`, the
   `if lang not in _F1_LANGS` line). Checks: in the rehearsal F1 fixed 0 documents in every code pack (code-cpp: 0 of
   54,588); a test row with a private email and phone in a C++ comment comes out unchanged with `lang_label` "code".
   Impact on code-cpp is small because StarCoder already masked most emails: 14 of the 54,588 cleaned documents still
   hold an email-like address (regex count, not checked by hand). Proposal: give F1 the language from the pack
   (`code-cpp` → `cpp`) or map the label in `clean()`; that path needs `tree_sitter_language_pack` in the job image.
5. **#78's finding 2 holds on code-cpp:** StarCoder's redaction sometimes replaced an identifier, and the placeholder
   replacement keeps code that calls an undefined name (e.g. `EXAMPLE_PASSWORD->password`). A script over the cleaned
   code-cpp finds 10 documents where `EXAMPLE_PASSWORD`/`EXAMPLE_KEY` is followed by `(`, `.`, `->` or `::`; checked by
   hand, 6 are real code and 4 are comments or strings. None in this sample; rare (6 of 54,588); the #78 proposal covers
   it.
6. **Watch: DA-E2-001's 10% bar.** In `579eed50abc89e4a` the byte-array lookup tables (real decoder tables) cover 9.61% of
   the file, just under the share at which DA-E2-001 drops the whole document. A slightly shorter file of the same kind
   would be dropped. No wrong drop was seen.
