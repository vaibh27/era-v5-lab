# Team 08 ClickHouse Store, JSONL Loader, Row Checker & Rollups

This folder implements the ClickHouse storage and rollup pipeline for ERA V5 training metrics (`metrics_raw`), 1 Hz GPU telemetry (`gpu_telemetry_1s`), and node health logs (`node_health`).

## 1. Run ClickHouse in Docker

Start ClickHouse `24.8-alpine` bound to `127.0.0.1:8123` (HTTP) and `127.0.0.1:9000` (native client):

```bash
docker run -d --name era-v5-clickhouse \
  -p 127.0.0.1:8123:8123 -p 127.0.0.1:9000:9000 \
  -e CLICKHOUSE_DB=default \
  -e CLICKHOUSE_DEFAULT_ACCESS_MANAGEMENT=1 \
  --ulimit nofile=262144:262144 \
  clickhouse/clickhouse-server:24.8-alpine
```

Apply the schema (`schema_v1.sql`) and rollup definitions (`rollups_v1.sql`):

```bash
docker exec -i era-v5-clickhouse clickhouse-client --multiquery < teams/08-monitoring/clickhouse/schema_v1.sql
docker exec -i era-v5-clickhouse clickhouse-client --multiquery < teams/08-monitoring/clickhouse/rollups_v1.sql
```

## 2. Schema (`schema_v1.sql`)

### `metrics_raw`

Stores per-step training metrics (`loss_ntp`, `loss_mtp`, `lr`, `tokens_per_second`, `gpu_alloc_gb`, `gradient_norm`, `model_flops_utilization`, `loader_wait_time`, etc.) and 1 Hz GPU telemetry (`gpu_utilization`, `gpu_memory_used`, `power_w`, `temp_c`, `sm_clock_mhz`, `mem_clock_mhz`):

| Column | Type | Description |
|---|---|---|
| `run_id` | `LowCardinality(String)` | Run identifier (e.g. `run_a`, `run_b`, `h200_v1`). |
| `step` | `UInt64` | Training optimizer step. |
| `time` | `DateTime64(3, 'UTC')` | Event UTC timestamp with millisecond precision. |
| `name` | `LowCardinality(String)` | Metric name. |
| `value` | `Nullable(Float64)` | Metric value; `NULL` when JSON contains `null` or non-finite `"nan"`, `"inf"`, `"-inf"`. |
| `rank` | `UInt16 DEFAULT 0` | Distributed rank or local GPU index. |

### `ingest_manifest`, `node_health` & `eval_mini`

- `ingest_manifest`: records `(run_id, source_file, jsonl_lines, metric_rows, null_rows, loaded_at)` for every loaded file.
- `node_health`: stores validated `v5-health/1` reports generated by Team 07's `health_check.py` and flattened by `teams/08-monitoring/health-check/health_check.py --clickhouse-jsonl`.
- `eval_mini`: stores Team 09's `eval_mini_v1.json` / `.jsonl` evaluation records (`teams/09-evaluation/results/eval_mini_v1_schema.md`, PR #186). The 8-field record key `(model, model_revision, format, item_set, task, num_fewshot, metric, filter)` and `value` are non-null; `checkpoint`, `derived_from`, `seed`, `stderr`, `dtype`, `n_items_total`, and `profile` (plus dotted flat columns `checkpoint_*`, `seed_*`, `harness_script_sha256`) are `Nullable(...)`.

## 3. Load Team 5, Team 6 & Team 9 Runs (`load_jsonl.py`)

`load_jsonl.py` loads Team 5's `run_a/` (baseline) and `run_b/` (reversible midpoint) `metrics.jsonl` files, Team 6's benchmark run JSONs (`h200_v1.json` from PR #135, `baseline_v0.json`), Team 6's live `step_timing` / `gpu_sample` JSONL streams, and Team 9's `eval_mini_v1.json` (`{"schema_version": "eval_mini_v1", "records": [...]}` or `.jsonl`). For Team 6 run JSONs, `metrics.mfu_method` and `metrics.mfu_scope` are stored as indicator rows `mfu_method.<method> = 1.0` and `mfu_scope.<scope> = 1.0` (defaulting legacy files without those keys to `mfu_method.g6-v1` and `mfu_scope.selected_gpu` per `METRICS.md`), and non-null `metrics.ke2_mean_support_len` is stored as `ke2_mean_support_len`:

```bash
# Load default Team 5 (run_a, run_b) and Team 6 (h200_v1.json) runs
python -I teams/08-monitoring/clickhouse/load_jsonl.py --defaults

# Or load explicit paths / directories (including Team 9 eval_mini_v1.json)
python -I teams/08-monitoring/clickhouse/load_jsonl.py \
  teams/05-architecture/experiments/evidence/run_a/ \
  teams/05-architecture/experiments/evidence/run_b/ \
  teams/06-performance/results/modal_gpu/h200_v1.json \
  teams/09-evaluation/results/eval_mini_v1.json
```

Reloading the same `run_id` is idempotent (existing rows for that `run_id` are deleted synchronously before inserting).

## 4. Verify Row & Line Counts (`check_rows.py`)

`check_rows.py` verifies for every loaded file that:
1. ClickHouse line/step count (`uniqExact((step, time, rank))` in `metrics_raw`) equals the source JSONL line count (`ch_lines == jsonl_lines`),
2. Total metric rows in `metrics_raw` match the source file (`ch_metric_rows == expected_metric_rows`),
3. Every `null` (or non-finite) value is stored as a `NULL` missing value in `metrics_raw` rather than dropped (`ch_null_rows == expected_null_rows`).

```bash
python -I teams/08-monitoring/clickhouse/check_rows.py --selftest
```

Output on the loaded Team 5 (`run_a`, `run_b`) and Team 6 (`h200_v1`) runs:

```text
  [PASS] selftest: jsonl_lines=3 == ch_lines=3, metric_rows=9, null_rows=4 (stored as NULL)
[PASS] run_id='h200_v1' source=teams/06-performance/results/modal_gpu/h200_v1.json | lines: file=150 ch=150 | metric_rows: file=220 ch=220 | null_rows: file=0 ch=0
[PASS] run_id='run_a' source=teams/05-architecture/experiments/evidence/run_a/metrics.jsonl | lines: file=40 ch=40 | metric_rows: file=240 ch=240 | null_rows: file=0 ch=0
```

## 5. Step & 1 s GPU Telemetry Rollups (`rollups_v1.sql`)

`rollups_v1.sql` defines both `AggregatingMergeTree` materialized rollups (`*_agg` + `*_mv`) and direct query views returning `min`, `max`, `mean`, `last`, and `count`:

- **Step rollups** (`intDiv(step, W) * W AS step_bucket`):
  - `metrics_rollup_10` ($W = 10$ steps)
  - `metrics_rollup_100` ($W = 100$ steps)
  - `metrics_rollup_1000` ($W = 1{,}000$ steps)
  - `metrics_rollup_10000` ($W = 10{,}000$ steps)
- **1-second GPU telemetry rollup** (`toStartOfSecond(time, 'UTC') AS time_1s`):
  - `gpu_telemetry_1s` (aggregates `gpu_utilization`, `gpu_util_pct`, `gpu_memory_used`, `mem_used_mib`, `mem_util_pct`, `gpu_alloc_gb`, `gpu_alloc_gib`, `sm_clock_mhz`, `mem_clock_mhz`, `power_w`, `temp_c`).

## 6. Node Health & Telemetry Loader (`load_node_logs.py`)

`load_node_logs.py` ingests validated node health JSON / JSONL reports (`v5-health/1` contract from Team 07's `health_check.py`) into the `node_health` table and streams GPU temperature/telemetry metrics into `metrics_raw`:

```bash
# Ingest default sample health report (teams/07-infrastructure/health/results/health_sample_v5.json)
python -I teams/08-monitoring/clickhouse/load_node_logs.py --defaults

# Parse without database write
python -I teams/08-monitoring/clickhouse/load_node_logs.py --dry-run <path_to_report_or_jsonl>

# Run offline unit/self tests
python -I teams/08-monitoring/clickhouse/load_node_logs.py --selftest
```
